# Theory-building scaffold

HarnessForge uses executable toy models to make proposed Harness Engineering mechanisms easier to reason about and eventually falsify.

## Four planes

1. Information — what the model knows now.
2. Continuity — what persists over time.
3. Action — what external systems the agent can affect.
4. Execution — how reasoning and action run, recover, and terminate.

## Three objectives

1. Reliability
2. Sovereignty
3. Efficiency

## Capability-multiplier hypothesis

For sufficiently structured tasks, recurring task complexity can sometimes be moved from repeated model inference into reusable architecture: context selection, deterministic tools, typed interfaces, workflow decomposition, verification, memory, and routing.

This motivates a testable hypothesis: a smaller model in a stronger harness can, on some tasks, meet or exceed the system-level utility of a larger model in a weaker harness.
